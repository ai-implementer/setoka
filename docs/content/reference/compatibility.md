# 互換性と更新

setoka は 0.x の版です。この間に何を変えうるか、変えるときにどう知らせるか、新しい版へ
上げるときに何をすればよいかをまとめます。

## 版の付け方

- **マイナー版**（`0.21.0` → `0.22.0`）— 新しい機能に加えて、非互換の変更を含むことがあります
- **パッチ版**（`0.21.0` → `0.21.1`）— 不具合の修正だけを入れます。誤った出力を直した結果として
  出力が変わることはありますが、設定キー・コマンドとフラグ・`--format json` のキー・診断ルールの
  名前の削除や改名はしません
- 1.0 以降の扱いは、1.0 を出すときに決めます

## 非互換の知らせ方

非互換の変更は、各版の[リリースノート](https://github.com/ai-implementer/setoka/releases)の
「非互換と注意」に必ず書きます。リリースノートの冒頭の概要にも、非互換の要点を 1 行で載せます。

CHANGELOG のファイルは置いていません。版ごとの変更の記録はリリースノートです。

## 約束の対象

次のものは、変えるときに必ず「非互換と注意」に書きます。パッチ版では削除・改名をしません。

| 対象 | 約束 |
| --- | --- |
| 設定（`setoka.toml`）のキー | 削除・改名はマイナー版だけで行います。知らないキーは位置付きの設定エラーになるので、更新後の最初の実行で分かります |
| コマンドとフラグ | 削除・改名はマイナー版だけで行います。改名するときは、できるだけ旧名も受け付けます（v0.17 で `search --json` を `--format json` にしたときも `--json` を残しました） |
| 終了コード | 0 = 成功・1 = 違反あり・2 = 実行エラー（[CLI コマンド](cli.md#終了コード規約)） |
| `--format json` の出力（`check` / `lint` / `search`） | キーを追加することはありますが、マイナー版でも削除・改名はしません |
| 診断ルールの名前 | `lint.rules` や frontmatter の `lintDisable` に書く名前なので、削除・改名はマイナー版だけで行います |
| frontmatter のキーと値の読み方 | 削除・改名・読み方の変更はマイナー版だけで行います |
| 出力の URL | 原稿のファイル名がそのまま URL になる規則を変えるときは、マイナー版で行います |

## 約束しないもの

次のものはどの版でも変わることがあります。

- **デフォルトテーマの中身**（テンプレートに渡す変数・HTML の構造・CSS のクラス・JS）。
  `theme/` でファイルを上書きしている場合は、更新のたびに差分を見直してください
  （[見た目の調整](../guide/appearance.md)）。テーマのファイルを変えた版では、リリースノートの
  「非互換と注意」に変えたファイルを挙げます
- **診断のメッセージの文言とログの書式**。プログラムで扱うときは `--format json` のルール名と
  位置を使ってください
- **キャッシュ（`.setoka/cache/`）の形式**。形式が変わった版の最初のビルドは、全ページを作り直します
  （自動で行います。`.setoka/` はいつ消しても安全です）
- **検索の索引（`_search/`）の形式**。ビルドのたびに作り直すので、することはありません。
  ただし更新の直後は、読者のブラウザに残った古い検索のファイルと新しいファイルが混ざり、
  キャッシュが切れるまで検索が動かないことがあります
- **ソースからビルドするときに要る Rust の版**（MSRV）。上げるのはマイナー版で、リリースノートに
  書きます
- **setoka 本体の Rust の API**（crates.io には公開していません）。同じリポジトリの tankan・mikan・
  kabosu は crates.io に公開しており、crates.io の版の規則（semver）に従います

## 新しい版に上げる手順

1. 今の版から新しい版までの、各版のリリースノートの「非互換と注意」を読みます
2. setoka を新しい版に入れ替えます（[インストール](../guide/install.md#インストール)と同じ手順）
3. GitHub Actions で配信している場合は、ワークフローの `SETOKA_VERSION` を新しい版に書き換えます
   （[配信とデプロイ](../guide/deploy.md#github-pages)）
4. `setoka check` を実行して、設定エラーと診断の変化を確かめます。設定のエラーは位置付きで出て、
   終了コード 2 で止まります
5. `theme/` でファイルを上書きしている場合は、デフォルトテーマの同じファイルと比べて変更を取り込みます。
   デフォルトテーマのファイルは、リポジトリの `crates/setoka-theme/assets/` を版のタグ（例: `v0.21.0`）で
   開くと、その版の中身を見られます
6. `setoka build` で作り直します。キャッシュの形式が変わった版では、最初のビルドが全ページを
   作り直すので、少し時間がかかります
